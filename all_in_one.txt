        .map(word => word.charAt(0).toUpperCase() + word.slice(1))
        .join(' ');
}

# GR Number Type Management System
## Complete Implementation Guide

---

## Overview
This system automatically detects and identifies whether a GR (Goods Receipt) number is:
- **Auto-generated** (Branch format: `101/001`, `102/015`, etc.)
- **Manual entry** (Any other format: `13435`, `ABC123`, etc.)

---

## Installation Steps

### Step 1: Run Database Migration
Execute this SQL migration file to add the `gr_type` column:

```sql
-- File: migrate_gr_type.sql
-- Run this in your MySQL database

-- Add gr_type column
ALTER TABLE `biltys`
ADD COLUMN `gr_type` ENUM('auto', 'manual') DEFAULT 'auto' AFTER `gr_number`;

-- Update existing records (Auto format: 101/001 pattern)
UPDATE `biltys`
SET `gr_type` = 'auto'
WHERE `gr_number` REGEXP '^[0-9]+/[0-9]+$';

-- Update existing records (Manual format: everything else)
UPDATE `biltys`
SET `gr_type` = 'manual'
WHERE `gr_number` NOT REGEXP '^[0-9]+/[0-9]+$' AND `gr_number` IS NOT NULL;

-- Add index for faster filtering
ALTER TABLE `biltys` ADD INDEX `idx_gr_type` (`gr_type`);
```

**How to run:**
1. Open phpMyAdmin or MySQL command line
2. Select your database
3. Copy and paste the SQL from `migrate_gr_type.sql`
4. Execute

---

## How It Works

### 1. Auto-Generated GR Numbers (Branch Format)
**Pattern:** `<branch_id>/<sequence>`
**Examples:** `101/001`, `102/015`, `103/0234`

- When user clicks "Get GR" or loads create page
- System checks last GR for the branch (e.g., 102)
- Increments sequence number (001 → 002)
- Automatically marked as type: **auto**
- **Badge:** Green "A" badge

### 2. Manual GR Numbers (User Entry)
**Pattern:** Any other format
**Examples:** `13435`, `ABC123`, `GR-2024-001`, `MANUAL-001`

- When user manually types GR number
- System detects it doesn't match branch/sequence pattern
- Automatically marked as type: **manual**
- **Badge:** Yellow "M" badge

## Key Functions

### detectGRType($grNumber)
**Purpose:** Auto-detect if GR is auto-generated or manual
**Logic:**
```php
// Empty = auto (will be generated)
if (empty(trim($grNumber))) return 'auto';

// Matches 101/001 pattern = auto
if (preg_match('/^\\d+\\/\\d+$/', trim($grNumber))) return 'auto';

// Everything else = manual
return 'manual';
```

### extractBranchFromGR($grNumber)
**Purpose:** Extract branch ID from auto-generated GR
**Example:** `102/001` → returns `102`

### formatGRWithType($grNumber, $grType)
**Purpose:** Format GR with HTML badge for display

# JSON Response Contamination - Fix Summary

## Problem
The browser was showing error: "Error searching consignor: Unexpected token '<', "<br /> <b>"..."

This indicated that API responses were contaminated with HTML error messages instead of returning clean JSON.

## Root Causes

### 1. **Include Path Errors**
The API files in `/bilty/create/api/` were trying to include files using wrong relative paths:
```php
// ❌ WRONG - These files don't exist relative to api/ directory
include "util.php";
include "config.php";
```

The correct path needed to account for the subdirectory nesting:
```php
// ✅ CORRECT - Navigate up to includes directory
include "../includes/util.php";
include "../includes/config.php";
```

### 2. **Missing Output Buffering**
API files didn't capture accidental output (warnings, errors), which gets mixed with JSON responses.

### 3. **db.php Error Handling**
The database connection file was using `die()` which outputs HTML `<br/>` tags instead of JSON for API requests.

## Solutions Applied

### Fix 1: Updated `/company/protect/db.php`
**Modified database connection error handling:**
- Added detection for API requests (checks if URI contains `/api/` or has `ajax` parameter)
- Returns JSON error response instead of HTML `die()` statement
```php
if ($isApiRequest) {
    header('Content-Type: application/json');
    echo json_encode(['success' => false, 'message' => 'Error message...']);
    exit;
}
```

### Fix 2: Added Output Buffering to All API Files
**Applied to:**
- `/bilty/create/api/search_party.php`
- `/bilty/create/api/station_search.php`
- `/bilty/create/api/product_search.php`
- `/bilty/create/api/get_party_products.php`
- `/bilty/create/api/get_gr.php`

**Pattern:**
```php
<?php
ob_start();  // Start capturing output

include "../../../protect/db.php";
include "../includes/util.php";
include "../includes/config.php";

try {
    // API logic here
    ob_end_clean();  // Clear buffer before sending JSON
    sendJsonResponse($success, $data, $message);
} catch (Exception $e) {
    ob_end_clean();  // Clear buffer before sending error JSON
    sendJsonResponse(false, [], "Error: " . $e->getMessage());
}
```

### Fix 3: Corrected Include Paths
**Changed in all API files:**
```
OLD:  include "util.php";        → NEW:  include "../includes/util.php";
OLD:  include "config.php";      → NEW:  include "../includes/config.php";
OLD:  include "../../protect/db.php";   → NEW:  include "../../../protect/db.php";
```

**Directory structure explanation:**
```
/company/
├── bilty/
│   ├── create/
│   │   ├── api/              ← API files here
│   │   │   ├── search_party.php
│   │   │   ├── station_search.php
│   │   │   ├── product_search.php
│   │   │   ├── get_party_products.php
│   │   │   └── get_gr.php
│   │   ├── includes/         ← util.php, config.php here
│   │   │   ├── util.php
│   │   │   ├── config.php
│   │   │   └── gr_handler.php
├── protect/                  ← db.php, auth.php here
│   ├── db.php
│   ├── auth.php
│   └── ...
```

**From `/api/` subdirectory:**
- Go up 1 level to `/create/` → `../`
- Go up 2 levels to `/bilty/` → `../../`
- Go up 3 levels to `/company/` → `../../../`

So: `../../../protect/db.php` = `/company/protect/db.php` ✅

# NMTC Logistics PHP Agent

You are an expert PHP developer embedded in the **NMTC transport/logistics management system** — a freight company web app running on XAMPP (Apache + MySQL + PHP). You know this codebase inside-out and always follow its established patterns without deviation.

## Domain Knowledge

| Module | What it is |
|---|---|
| **bilty / GR** | Goods Receipt — the primary shipping document. Has consignor, consignee, items, freight charges, GR number. |
| **challan** | Dispatch note — groups bilties onto one vehicle trip with driver, agent, financial totals. |
| **bill** | Invoice generated from bilty data. |
| **party** | Customers (consignors/consignees) with optional per-party product lists. |
| **product** | Goods/commodity catalog. |
| **station** | Delivery destinations/routes. |
| **vehicle** | Fleet — trucks/lorries used in challans. |
| **agent** | Brokers or transport agents used in challans. |
| **ledger** | Financial ledger per party. |
| **admin** | Platform super-admin — manages companies (separate auth context). |

## Architecture

- **No framework** — procedural PHP with `include`/`include_once` for composition.
- **MySQL via raw MySQLi** — absolutely no ORM or query builder.
- **Multi-tenant** — every DB query filters by `$_SESSION['company_id']` (the tenant key).
- **Dual auth roles**: `company` user (`$_SESSION['company_id']`) and `admin` (`$_SESSION['admin_login']`).
- **Module structure**: `module/index.php` (page), `module/create/api/*.php` (JSON APIs).

## Mandatory Coding Rules

### Security (non-negotiable)
- **Always use prepared statements** (`$conn->prepare()` + `bind_param()`). Never interpolate user input into SQL.
